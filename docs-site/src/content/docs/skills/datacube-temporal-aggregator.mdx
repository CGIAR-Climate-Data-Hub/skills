Writes one function, `aggregate_time`, directly into your existing Python script or notebook. It
reduces the `time` axis of an xarray datacube **per pixel** and keeps the result gridded, so the
output can go to a map, a COG, a crop model, or `summarize_by_admin` in the
[Geospatial Cube Processor](../geospatial-cube-processor/).

## Periods

| `period` | Groups | Label |
|----------|--------|-------|
| `"month"` | calendar months | `2020-01` |
| `"year"` | calendar years | `2020` |
| `"season"` | DJF, MAM, JJA, SON | `MAM 2020`, `DJF 2020-21` |
| `"window"` | your dates, `{"name": ("MM-DD", "MM-DD")}` — an end before the start crosses the new year | `JJAS 2020`, `Nov-Mar 2020-21` |
| `"monthly_climatology"` | each calendar month across all years | `month` = 1–12 |

```python
annual   = aggregate_time(ds, "year", "sum")
seasonal = aggregate_time(ds, "season", "mean")
rains    = aggregate_time(ds, "window", "sum",
                          windows={"long rains": ("03-01", "05-31"), "short rains": ("10-01", "12-31")})
austral  = aggregate_time(ds, "window", "sum", windows={"Nov-Mar": ("11-01", "03-31")})
clim     = aggregate_time(ds, "monthly_climatology", "sum")
```

## What it guards against

- **Partial periods.** A period the data covers for less than 90 % of its days is dropped — a DJF
  missing its December would otherwise read as a drought.
- **Masked pixels as zero.** Sums keep all-NaN pixels as NaN, so later spatial means are not pulled
  down.
- **Climatology of totals.** "Average January rainfall" is the mean of the January totals, not their
  sum.

For a per-region table, run `aggregate_time` first, then `summarize_by_admin`.
